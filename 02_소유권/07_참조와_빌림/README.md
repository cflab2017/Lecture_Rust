# 07. 참조와 빌림 (&T, &mut T, 빌림 규칙)

6 편에서 본 것처럼, `String` 같은 값을 함수에 넘기면 소유권이 통째로 이동합니다. 매번 반환값으로 돌려받는 건 번거롭죠. Rust 는 소유권을 옮기지 않고 값을 잠깐 "빌려" 보는 **참조(reference)** 를 제공합니다. 이번 편에서 익히는 빌림 규칙은 안전한 동시성으로 곧장 이어집니다.

## 학습 목표

- 공유 참조 `&T` 와 가변 참조 `&mut T` 를 구분해서 사용한다.
- 빌림 규칙(가변 1개 vs 불변 N개)을 외우고 코드에서 적용한다.
- 댕글링 참조가 컴파일 시 차단되는 방식을 이해한다.
- 함수에 참조를 받아 호출자가 값을 계속 쓸 수 있게 한다.

## 핵심 개념

### 1) 공유 참조 `&T`

읽기 전용 빌림입니다. 같은 시점에 여러 개가 동시에 존재할 수 있습니다.

```rust
fn len_of(s: &String) -> usize { s.len() }
let s = String::from("Rust");
let n = len_of(&s);   // 소유권 이동 X
```

### 2) 가변 참조 `&mut T`

수정 가능한 빌림입니다. 한 시점에 **단 하나** 만 존재할 수 있고, 가변 참조가 살아 있는 동안 다른 어떤 참조(불변·가변)도 만들 수 없습니다.

```rust
fn append_excl(s: &mut String) { s.push('!'); }
let mut s = String::from("안녕");
append_excl(&mut s);
```

### 3) 빌림 규칙

> 같은 시점에 다음 둘 중 **하나만** 허용된다.
> - 불변 참조 **여러 개**
> - 가변 참조 **하나**

이 규칙 덕분에 데이터 레이스가 컴파일 단계에서 차단됩니다. Rust 1.31 이후의 **non-lexical lifetimes (NLL)** 덕분에 "마지막 사용 시점" 이후에는 참조가 자동으로 비활성화되어 같은 변수에 새 참조를 만들 수 있습니다.

### 4) 댕글링 참조 차단

이미 drop 된 값을 가리키는 참조(dangling reference)는 컴파일러가 막아 줍니다. 함수에서 지역 변수의 참조를 그대로 반환하려고 하면 라이프타임 에러가 납니다 — 자세한 내용은 9 편에서 다룹니다.

## 예제로 보기

### 예제 1 — `ex01_share.rs` : 공유 참조로 빌리기

```rust
// 7편 예제 1: 공유 참조(&T) 로 값을 "빌려" 보기
//
// 참조를 받으면 소유권이 이동하지 않으므로, 호출자는 변수를 계속 쓸 수 있다.

fn len_of(s: &String) -> usize {
    s.len()
} // 여기서 s 는 빌린 참조라 drop 되지 않음

fn main() {
    let s = String::from("Hello, Rust!");
    let n = len_of(&s); // 참조 만들기: `&s`
    println!("\"{s}\" 의 길이는 {n}");

    // 참조는 여러 개를 동시에 가질 수 있다(불변일 때).
    let r1 = &s;
    let r2 = &s;
    println!("같은 값을 두 참조로: {r1} / {r2}");
}
```

### 예제 2 — `ex02_mut.rs` : 가변 참조로 수정

```rust
// 7편 예제 2: 가변 참조(&mut T) 로 값을 수정하기
//
// 가변 참조를 만들려면 원본도 `mut` 이어야 하고,
// 같은 시점에 가변 참조는 **단 하나** 만 존재할 수 있다.

fn append_excl(s: &mut String) {
    s.push('!');
}

fn main() {
    let mut greeting = String::from("안녕");
    append_excl(&mut greeting);
    append_excl(&mut greeting);
    println!("{greeting}");

    // 직접 가변 참조를 만들어 사용하기
    let r = &mut greeting;
    r.push_str(" Rust");
    println!("{r}");
    // 이 시점부터는 r 을 더 쓰지 않으니 다른 참조를 만들어도 됩니다.
    println!("(원본) {greeting}");
}
```

### 예제 3 — `ex03_rules.rs` : 빌림 규칙

```rust
// 7편 예제 3: 빌림 규칙 — 같은 시점에
//   (a) 가변 참조 1개  또는
//   (b) 불변 참조 N개
// 둘 중 하나만 허용됨.

fn main() {
    let mut v = vec![1, 2, 3];

    // 불변 참조 여러 개는 OK
    let a = &v;
    let b = &v;
    println!("a = {a:?}, b = {b:?}");
    // 위 두 참조는 여기서 마지막 사용 → 이후로는 비활성화

    // 비활성화된 뒤에는 가변 참조를 새로 만들 수 있다.
    let m = &mut v;
    m.push(4);
    println!("m = {m:?}");

    // 댕글링 참조도 컴파일러가 막아 줍니다:
    // fn dangle() -> &String {
    //     let s = String::from("oops");
    //     &s   // ❌ s 는 함수가 끝나면 drop 됨
    // }
}
```

## 자주 하는 실수

### Q. `&String` 보다 `&str` 을 받는 게 좋다고 들었어요.

A. 맞습니다. `&str` 은 `String` 의 슬라이스이기도 하고 문자열 리터럴이기도 해서 더 범용적입니다. 다음 편에서 슬라이스를 자세히 다룹니다. 일단 이번 편에서는 빌림 자체를 익히기 위해 `&String` 을 썼습니다.

### Q. 가변 참조를 만들었더니 "cannot borrow as mutable" 에러가 납니다.

A. 원본 변수가 `mut` 으로 선언되었는지 확인하세요. `let mut s = ...;` 처럼 가변으로 선언해야 `&mut s` 를 만들 수 있습니다.

### Q. 같은 변수에 가변 참조 두 개를 만들 수 있나요?

A. 같은 **시점** 에는 안 됩니다. 첫 번째 가변 참조의 사용이 끝난(마지막으로 읽힌) 뒤에는 NLL 덕분에 새 가변 참조를 만들 수 있습니다.

### Q. 참조도 소유권이 있나요?

A. 참조 자체는 단순한 포인터라 작은 Copy 타입처럼 동작합니다. 다만 "참조가 가리키는 값" 의 소유자는 여전히 원래 변수입니다.

## 정리

- `&T` 는 읽기 전용 빌림, `&mut T` 는 수정 가능 빌림.
- 한 시점에 가변 1개 또는 불변 N개 — 동시 허용 안 됨.
- 참조를 받는 함수는 호출자의 값을 그대로 쓸 수 있게 해 준다.
- 댕글링 참조는 컴파일러가 자동으로 차단한다.
