# 06. 소유권의 세 규칙 + move/copy

Rust 가 가비지 컬렉터 없이도 메모리 안전성을 보장하는 비결이 **소유권(ownership)** 입니다. 모든 값은 정확히 하나의 "소유자" 를 가지고, 소유자가 스코프를 벗어나면 값이 즉시 해제됩니다. 이번 편에서 세 규칙을 익혀 두면 이후 모든 컴파일러 에러를 훨씬 잘 읽을 수 있습니다.

## 학습 목표

- 소유권의 세 규칙을 외우고 코드에서 식별한다.
- 스택과 힙의 차이를 알고, 어떤 타입이 어디에 저장되는지 안다.
- `Copy` 타입과 그렇지 않은 타입(예: `String`)을 구분한다.
- 함수에 값을 넘기면 소유권이 어떻게 이동하는지 추적한다.

## 핵심 개념

### 1) 소유권의 세 규칙

> 1. Rust 의 모든 값은 **소유자(owner)** 라고 부르는 변수를 가진다.
> 2. 한 시점에 소유자는 **단 하나** 뿐이다.
> 3. 소유자가 **스코프를 벗어나면** 값은 즉시 **drop** 된다.

이 세 규칙만으로 use-after-free, double-free 같은 메모리 버그가 컴파일 단계에서 차단됩니다.

### 2) 스택과 힙

- **스택**: 크기가 고정된 값(i32, bool, char, 고정 튜플·배열 등). 빠르고, 자동 해제됨.
- **힙**: 크기가 가변이거나 동적인 값(`String`, `Vec<T>`, `Box<T>`). 할당·해제 비용이 있음.

`String` 은 힙에 실제 글자 데이터를 두고, 스택에는 `(포인터, 길이, 용량)` 의 메타데이터만 둡니다.

### 3) 이동(move) — 힙 소유 타입

`String` 같은 비-Copy 타입은 대입·함수 호출에서 **소유권이 이동** 합니다. 이동된 변수는 그 시점부터 사용 불가입니다.

```rust
let s1 = String::from("안녕");
let s2 = s1;     // s1 → s2 이동
// println!("{s1}"); // ❌ 더 이상 유효하지 않음
```

### 4) 복사(copy) — Copy 트레잇 구현 타입

스칼라 타입(`i32`, `f64`, `bool`, `char`, 그리고 그들만으로 구성된 튜플/배열)은 `Copy` 트레잇이 구현되어 있습니다. 대입·전달 시 **비트 복사** 만 일어나고 원본도 그대로 사용 가능합니다.

| 타입 예시 | move/copy | 이유 |
|----------|-----------|------|
| `i32`, `f64`, `bool`, `char` | copy | 크기 고정·스택 저장 |
| `(i32, i32)`, `[u8; 4]` | copy | 모든 원소가 Copy |
| `String`, `Vec<T>`, `Box<T>` | move | 힙 자원 소유 |

### 5) 함수 호출과 소유권

함수에 값을 인수로 넘기면 매개변수가 새 소유자가 됩니다. 같은 값을 호출자가 계속 사용하려면 (a) 반환값으로 돌려받거나 (b) 다음 편의 **참조(reference)** 를 씁니다.

## 예제로 보기

### 예제 1 — `ex01_move.rs` : String 의 소유권 이동

```rust
// 6편 예제 1: String 의 소유권 이동(move)
//
// 힙에 데이터를 가지는 타입(String, Vec, Box 등) 은 대입이나 함수 호출에서
// 값이 "이동" 됩니다. 이동된 변수는 더 이상 사용할 수 없습니다.

fn main() {
    let s1 = String::from("안녕"); // s1 이 힙 데이터의 소유자
    let s2 = s1;                    // 소유권이 s2 로 이동
    // println!("{s1}");            // ❌ 컴파일 에러: s1 은 더 이상 유효하지 않음
    println!("s2 = {s2}");

    let s3 = String::from("Rust");
    take(s3);                       // 함수에 넘기면 인수로 소유권 이동
    // println!("{s3}");            // ❌ s3 도 더 이상 유효하지 않음

    println!("스코프가 끝나면 소유자가 drop 되어 메모리가 해제됩니다.");
}

fn take(s: String) {
    println!("take 가 받은 값: {s}");
    // 함수가 끝나면서 s 가 drop 됨
}
```

### 예제 2 — `ex02_copy.rs` : Copy 타입은 복사

```rust
// 6편 예제 2: Copy 트레잇이 구현된 타입 — 복사로 동작
//
// 스칼라 타입(i32, f64, bool, char, ...) 과 그들로만 구성된 튜플은 `Copy` 입니다.
// 대입·전달 시 비트 복사가 일어나므로 "이동" 처럼 보이지 않습니다.

fn main() {
    let a = 10;
    let b = a;        // a 의 비트가 b 로 복사
    println!("a = {a}, b = {b}"); // a 도 여전히 사용 가능

    let p = (1, 2);   // (i32, i32) 도 Copy
    let q = p;
    println!("p = {:?}, q = {:?}", p, q);

    show(a);
    println!("show 호출 후에도 a = {a}");
}

fn show(n: i32) {
    println!("show: {n}");
}
```

### 예제 3 — `ex03_return.rs` : 반환으로 소유권 회수

```rust
// 6편 예제 3: 반환값으로 소유권 회수하기
//
// 함수에 String 을 넘기면 소유권이 이동합니다. 다시 쓰고 싶다면
// 반환값으로 돌려받거나, 다음 편에서 배울 "참조" 를 쓰면 됩니다.

fn main() {
    let s = String::from("hello");
    let s = grow(s); // s 를 넘기고 반환된 새 String 을 다시 s 에 묶음 (섀도잉)
    println!("결과: {s}");
}

fn grow(mut s: String) -> String {
    s.push_str(", world!");
    s // 소유권을 호출자에게 돌려줌
}
```

## 자주 하는 실수

### Q. `String` 을 함수에 넘긴 뒤 호출자에서 다시 쓰려면?

A. 두 가지 방법이 있습니다. (1) 함수가 같은 `String` 을 다시 반환하도록 만들거나, (2) **참조** (`&String` 또는 `&str`) 로 빌려주기. 보통 (2) 가 자연스럽습니다 — 다음 편에서 배웁니다.

### Q. `let s2 = s1;` 이 이동인데, `let n2 = n1;` (i32) 은 왜 복사인가요?

A. 컴파일러가 타입에 `Copy` 트레잇이 구현되어 있는지를 보고 결정합니다. `i32` 는 `Copy`, `String` 은 아닙니다. 같은 문법이지만 타입에 따라 다르게 동작합니다.

### Q. `String` 도 복사하고 싶어요.

A. 명시적으로 `s1.clone()` 을 호출하면 힙 데이터까지 복제한 새 `String` 이 만들어집니다. 비싸므로 정말 필요할 때만 쓰세요.

### Q. drop 은 언제 일어나나요?

A. 변수가 스코프 `{ ... }` 를 벗어나는 순간입니다. `Drop` 트레잇이 구현된 타입(`String`, `Vec`, `Box` 등)은 이 때 자동으로 자원 해제 코드가 호출됩니다. 명시적으로 `drop(value)` 함수로 일찍 떨어뜨릴 수도 있습니다.

## 정리

- 모든 값은 단 하나의 소유자를 가지며, 소유자가 스코프를 벗어나면 drop 된다.
- 힙 자원 타입(`String`, `Vec`, `Box`)은 대입·전달 시 이동(move) 한다.
- 스칼라 타입은 `Copy` 가 구현되어 있어 복사로 동작한다.
- 함수에 넘긴 값을 다시 쓰려면 반환하거나 다음 편의 참조를 쓴다.
